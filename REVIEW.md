# Review guide

Reviewers report correctness gaps and requirement gaps only. Style, naming and taste are out of scope unless they break a rule below.

## What to check

1. **The brief.** Every requirement in the active brief (`docs/briefs/`) is met, or its gap is listed in the checkpoint (`docs/cp/`).
2. **Reference geometry.** Reference area, mean aerodynamic chord and sweep definitions match the source report exactly. Sweep conversions between chord fractions are applied where an equation needs a different chord line.
3. **Data honesty.**
   - Measured, model and outside-model-range values are labelled as such, in code and on screen.
   - No measured point is smoothed, interpolated or invented.
   - No computed value is shown as measured.
   - No constant is tuned to pass a test. A calibrated constant names the single dataset it was calibrated on and is validated on the others.
   - The validation report is generated by `pnpm validate`, not edited by hand.
4. **Uncertainty.** Each digitized point carries both passes, its digitization uncertainty and its total uncertainty (root-sum-square with the report's declared accuracy).
5. **Model validity.** Equations are not evaluated outside their stated range without being flagged. Equations not confirmed against an open source carry the `UNVERIFIED` marker.
6. **Units.** Every number shown to the user has a unit or is explicitly dimensionless, and has a source.
7. **Public repository hygiene.** No secrets, no personal paths, no third-party PDFs or scans committed. No `LICENSE` file.
8. **Checks.** `pnpm test`, `pnpm typecheck`, `pnpm lint` pass; the browser console is clean.

## How to report

One line per finding: file and line, the requirement or invariant it breaks, and a concrete failing case.
